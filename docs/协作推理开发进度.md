## P1 接口与兼容

- `GET /api/v1/model-artifacts` 列出模型；`POST` 登记不可变元数据。字段为 `id/name/format/file/revision/sha256/architecture/quantization/weight_mib/layers/context_limit`，`format=gguf`；`file` 是模型目录内的文件名，校验和是完整文件的 SHA-256。相同 ID 重复登记相同内容允许，修改内容必须使用新 ID。
- 部署新增 `backend`：省略为 `llama_rpc`；`llama_local` 只允许一个节点，要求 Agent 上报对应能力。`model_ref` 可引用目录并固定文件、权重大小、层数和校验和；旧的直接 GGUF 文件部署继续支持。
- 本机内存模式填写 `layers/gpu_layers/ram_mib`，另有默认 4096 MiB 的 `host_reserve_mib`。RAM 预留至少覆盖整个权重文件 + KV + 运行余量，以覆盖加载峰值。GPU 按层数估算，仍必须通过实际加载与预热。
- `ram_mib` 是调度预留，不是操作系统硬内存上限；不保证外部进程不会同时消耗内存。关闭 mmap 和按需磁盘读取；不主动配置磁盘卸载或系统 swap。节点独占和完整停止确认维持原有语义。
- Linux 采集 `/proc` 并限制在 cgroup v1/v2 可用内存范围内；Windows 使用系统内存与 CPU 时间接口。未采集的主机数据为 `null`/省略，禁止以 0 伪装成有效观测。
- 新 Prometheus 指标：`platform_host_memory_{total,available,reserved}_bytes`、`platform_host_cpu_count`、`platform_host_cpu_utilization_percent`。心跳过期停止导出实时数值。
- 校验和验证在后台执行，支持取消，不阻塞心跳。模型健康接口成功后还必须实际生成 1 token，最多等待 60 秒；健康检查退化立即关闭新推理准入。加载超时只适用于首次就绪之前。
- 快照 v2 保存模型目录、RAM 预留和能力；读取 v1 时旧部署归为 RPC。控制面重启后清除观测新鲜度并保留资源所有权。旧程序不能读取 v2；升级前备份，回滚先停止新后端部署。

## P2 接口与测量口径

- `GET/POST/PUT /api/v1/network-groups`：最多 64 组，每组 1–8 台登记节点。字段 `id/name/node_ids/max_rtt_ms/max_jitter_ms/min_mbps/max_age_seconds`；默认 20 ms / 10 ms / 100 Mbps / 300 秒。节点成员由操作员管理；组内有未终止部署时拒绝修改，不自动迁移运行中的模型。
- `POST /api/v1/network-probes` 接收 `source_id/target_id`，不接收任意 URL。控制面从登记信息中固定两端地址，通过认证的 Agent 心跳下发；同一节点只能参与一个探测，同方向冷却 30 秒，任务 45 秒失效。`GET` 查看最近最多 128 项状态。
- Agent 每次做 5 个 HTTP 往返，P95 为这 5 次的最大值；抖动为相邻采样差值的平均绝对值。随后上传 1 MiB 随机数据，记录包含请求/应答开销的有效速率。不是网卡理论上限，也不包含模型计算成本。
- 每个 HTTP 调用最多 5 秒，总探测 15 秒；接收端限制恰好 1 MiB，单并发、有读取截止时间。仅连接私网、回环或 VPN 常用的 RFC 6598 地址；不跟随重定向，不使用系统代理，逐个检查 DNS 结果并连接已检查的 IP。目标必须返回正确的 Agent ID。
- `GET /api/v1/network-links?group_id=组标识` 返回该组有效期下的状态，省略为 300 秒。双向结果独立存储；未测量、失败、过期、节点失联及地址改变均不满足新组调度策略。最多保存 4096 条最近链路。
- 对登记的 RPC 网络组，最多枚举 255 个节点子集，检查同引擎版本、容量、两方向 RTT/抖动/速率；优先使用更少节点，再选择最差方向 RTT 更低的组合。旧 Agent 的网络组标签仍保留原行为，预览明确提示尚未配置测量策略。
- 快照 v3 保存网络组与最新链路，兼容读取 v1/v2；重启后链路统一失效，探测任务不重放。重新测量后才能调度；已运行部署不因测量过期被停止。不能用旧程序直接读取 v3。
- Agent 的 `network-probe` 服务显示状态、真实请求数、收发字节、错误和延迟；Prometheus 增加 `platform_network_link_valid`、观测时间、RTT、抖动、上传速率。过期/失败结果不导出实时速率数值。
- 自动化覆盖双向约束、慢链路、过期与地址变化、重启、归属校验、重复投递、有界载荷、取消、重定向/公网拒绝、活跃组修改拒绝以及贪心放置会漏选的可用节点组合。控制台完成同机两个 Agent 的真实 HTTP 测量与可视检查；不作为异地带宽证据。

## P4 请求入口与保护（2026-10-02）

- `GET/POST/PUT /api/v1/model-pools` 管理入口；字段 `id/model_ref/backend/deployment_ids`。最多 64 个入口、每个 1–32 个部署，必须引用同一不可变模型目录项和后端。已有入口不能更换模型身份，只能调整相容成员；停止成员可保留，但不接收新请求。旧的直接文件部署需新建引用目录的部署后才能进入池。
- `GET /v1/models` 列出登记的入口，包括暂时无就绪成员的入口；`POST /v1/chat/completions` 使用入口 ID 作为 `model`。两者与 `/api/` 使用同一认证。旧部署推理路径继续可用，并共享同一部署额度；推理流不持有状态落盘锁。
- 每部署并发 1、等待队列 8、排队最多 3 秒。选择就绪且报告/节点心跳有效的部署，优先未完成请求更少的实例，再参考首 token 的指数移动平均。排队后再次检查可用性。满队列或排队超时返回 429；没有就绪成员返回 503。
- 首 token 最多等待 15 秒，生成后连续 10 秒无有效增量即中止；120 秒总时限包含请求解析和排队。请求上传另限 3 秒、最多 2 MiB。客户端关闭连接会取消排队或上游调用；控制台测试按钮支持取消，离开模型页也会取消。
- 普通 JSON 请求也以 SSE 请求上游，再聚合为 JSON，以检查真实进度。角色、HTTP 头和 SSE 注释不计为首 token；内容、推理内容、拒绝文本及工具调用增量计为进度。仅支持 `n=1`，事件最多 1 MiB、完整响应最多 8 MiB。上游必须支持流式聊天；保留实际 usage，不推算 token 数。
- 请求一旦选定部署就不迁移、不重试。流式响应开始后出现错误时发送 SSE `error` 并结束，不发送成功的 `[DONE]`；未开始响应则返回相应 HTTP 错误。上游 EOF、无 finish_reason 的结束均视为失败。
- 新增 `GET /api/v1/monitor/inference`，以及 `platform_inference_*` 的执行、排队、完成、失败、取消、拒绝、各类超时和 TTFT 直方图。TTFT 包含入队时间，没有输出的失败不填 0。计数从当前控制面启动开始；Prometheus 保存历史，不能把请求块数量当 token 数。统一路由与部署网关分别计流量，不应跨层求和。
- 每次请求返回 `X-Request-ID`，控制面完成日志包含请求 ID、模型、部署、结果、耗时；不记录消息正文和令牌。Grafana 增加执行/队列、首 token P95、失败/取消、队列拒绝面板；告警总数增至 7 条，可捕捉 HTTP 200 之后的生成失败。
- 快照 v4 保存入口身份与成员，读取 v1/v2/v3；运行中的请求及队列不持久化。控制面重启会断开请求，客户端需明确重新发起，不自动重放。升级前已备份本地 18090 状态。

验证：全部 Go 包、`go vet`、WSL Linux race、前端构建通过。自动化覆盖认证、相容性、并发冲突、共享额度、排队取消/超时、停止后的准入复查、心跳不能伪装进度、生成停滞、总超时、异常 EOF、工具调用聚合及取消传播。真实 RTX 5060 + SmolLM2 135M 冒烟中，统一 JSON、旧入口 JSON、SSE 均完成；另一次 SSE 中途取消，记录 3 次完成、1 次取消，执行/队列归零。停止后 Agent 确认退出并释放 GPU/RAM。这不是 13B 或多物理机吞吐验收。

## P3 私有链路验证与接入准备（2026-10-02）

- 新 `safetensors` 目录格式：清单 SHA-256、模型/tokenizer 固定版本、精度、层数、上下文、每层 GPU 估计、加载 RAM、FP16 KV 每层每 token 字节数。`petals` 必须引用已登记目录；GGUF 与 safetensors 不跨后端混用。运行时逐文件校验，核对清单与调度预算，禁用远程模型代码和联网下载。
- 私有 Agent 固定运行配置 `petals-22afba6-torch2.8-cu128-bnb0.48.1-v1`，持久 Peer ID 和明确的私网引导列表。调度要求网络组的双向新鲜测量、相同运行配置/引导、独立 GPU/身份/端口、每台足够加载 RAM；将全部层分成连续、无遗漏、无重叠的固定范围。
- 工作进程在后台校验/加载，Agent 心跳继续。所有块健康后再启动协调网关；完整模型实际预热成功才 ready。健康退化关闭准入，保留所有权；正常停止先排空网关，租约丢失则终止所属进程组。父进程意外退出也清理其进程组，并用真实子服务端口验证。
- 网关固定允许的 Peer ID，一次尝试；支持有界文本聊天 JSON/SSE、实际 token 用量和客户端取消。取消期间仍占据会话额度，直到计算线程退出；若 native/RPC 操作超过取消宽限则退出网关，由 Agent 处理。中途失败发送错误，不发送成功结束标记。
- 每个块服务记录实际 protobuf 接收/发送字节、会话、错误、KV 和 CUDA 分配/保留字节。服务监控新增 Petals 分类和块范围；引导服务提供独立容器 NIC 计数及健康出口，控制面的 `traffic_url` 可采集远端引导容器，不把探针载荷当业务流量。
- 快照 **v5** 保存固定私有身份、块范围与封装预算，读取 v1–v4；重启继续保留资源所有权但使观测失效。`18090` 升级前已备份状态。回滚需要恢复备份，旧程序不能读取 v5。

验证：10 项 Python 单测，Windows 全部 Go 测试/vet、WSL 与 Go 1.22 容器 race、前端构建和浏览器表单检查。实际 GPU 运行链路完成 JSON/SSE、取消后的活动会话与 KV 归零、生成中杀死工作进程后有界失败；两服务均记录到非零真实载荷。实际 Agent 使用正常 45 秒租约，在测试控制连接中断后约 48 秒停止所属网关和 GPU 进程，返回 503，并在恢复连接后确认 failed/stopped。

这些实际 GPU 测试仍只使用一张卡和随机小模型。测试控制连接不是生产调度器，第二个进程没有冒充独立物理资源。尚无真实多机 13B TTFT P95/持续 token/s/异地恢复结论；旧会话 KV 丢失后不自动恢复，替代节点须建立新部署。
