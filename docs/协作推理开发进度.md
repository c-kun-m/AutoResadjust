# 普通显卡协作推理开发进度

## 验收目标

2–4 台独立 NVIDIA 主机，可信团队私网，局域网与异地混合，在线聊天优先。首期技术基准为 13B 级模型；模型已加载、256 token 输入、最多 128 token 输出时，目标为 P95 首 token ≤5 秒、生成速度中位数 ≥5 token/s。网络仿真或测试子进程不能替代真实多机推理证明。

## P1 接口与兼容

- `GET /api/v1/model-artifacts` 列出模型；`POST` 登记不可变元数据。字段为 `id/name/format/file/revision/sha256/architecture/quantization/weight_mib/layers/context_limit`，`format=gguf`；`file` 是模型目录内的文件名，校验和是完整文件的 SHA-256。相同 ID 重复登记相同内容允许，修改内容必须使用新 ID。
- 部署新增 `backend`：省略为 `llama_rpc`；`llama_local` 只允许一个节点，要求 Agent 上报对应能力。`model_ref` 可引用目录并固定文件、权重大小、层数和校验和；旧的直接 GGUF 文件部署继续支持。
- 本机内存模式填写 `layers/gpu_layers/ram_mib`，另有默认 4096 MiB 的 `host_reserve_mib`。RAM 预留至少覆盖整个权重文件 + KV + 运行余量，以覆盖加载峰值。GPU 按层数估算，仍必须通过实际加载与预热。
- `ram_mib` 是调度预留，不是操作系统硬内存上限；不保证外部进程不会同时消耗内存。关闭 mmap 和按需磁盘读取；不主动配置磁盘卸载或系统 swap。节点独占和完整停止确认维持原有语义。
- Linux 采集 `/proc` 并限制在 cgroup v1/v2 可用内存范围内；Windows 使用系统内存与 CPU 时间接口。未采集的主机数据为 `null`/省略，禁止以 0 伪装成有效观测。
- 新 Prometheus 指标：`platform_host_memory_{total,available,reserved}_bytes`、`platform_host_cpu_count`、`platform_host_cpu_utilization_percent`。心跳过期停止导出实时数值。
- 校验和验证在后台执行，支持取消，不阻塞心跳。模型健康接口成功后还必须实际生成 1 token，最多等待 60 秒；健康检查退化立即关闭新推理准入。加载超时只适用于首次就绪之前。
- 快照 v2 保存模型目录、RAM 预留和能力；读取 v1 时旧部署归为 RPC。控制面重启后清除观测新鲜度并保留资源所有权。旧程序不能读取 v2；升级前备份，回滚先停止新后端部署。

## P2 接口与测量口径

- `GET/POST/PUT /api/v1/network-groups`：最多 64 组，每组 1–8 台登记节点。字段 `id/name/node_ids/max_rtt_ms/max_jitter_ms/min_mbps/max_age_seconds`；默认 20 ms / 10 ms / 100 Mbps / 300 秒。节点成员由操作员管理；组内有未终止部署时拒绝修改，不自动迁移运行中的模型。
- `POST /api/v1/network-probes` 接收 `source_id/target_id`，不接收任意 URL。控制面从登记信息中固定两端地址，通过认证的 Agent 心跳下发；同一节点只能参与一个探测，同方向冷却 30 秒，任务 45 秒失效。`GET` 查看最近最多 128 项状态。
- Agent 每次做 5 个 HTTP 往返，P95 为这 5 次的最大值；抖动为相邻采样差值的平均绝对值。随后上传 1 MiB 随机数据，记录包含请求/应答开销的有效速率。不是网卡理论上限，也不包含模型计算成本。
- 每个 HTTP 调用最多 5 秒，总探测 15 秒；接收端限制恰好 1 MiB，单并发、有读取截止时间。仅连接私网、回环或 VPN 常用的 RFC 6598 地址；不跟随重定向，不使用系统代理，逐个检查 DNS 结果并连接已检查的 IP。目标必须返回正确的 Agent ID。
- `GET /api/v1/network-links?group_id=组标识` 返回该组有效期下的状态，省略为 300 秒。双向结果独立存储；未测量、失败、过期、节点失联及地址改变均不满足新组调度策略。最多保存 4096 条最近链路。
- 对登记的 RPC 网络组，最多枚举 255 个节点子集，检查同引擎版本、容量、两方向 RTT/抖动/速率；优先使用更少节点，再选择最差方向 RTT 更低的组合。旧 Agent 的网络组标签仍保留原行为，预览明确提示尚未配置测量策略。
- 快照 v3 保存网络组与最新链路，兼容读取 v1/v2；重启后链路统一失效，探测任务不重放。重新测量后才能调度；已运行部署不因测量过期被停止。不能用旧程序直接读取 v3。
- Agent 的 `network-probe` 服务显示状态、真实请求数、收发字节、错误和延迟；Prometheus 增加 `platform_network_link_valid`、观测时间、RTT、抖动、上传速率。过期/失败结果不导出实时速率数值。
- 自动化覆盖双向约束、慢链路、过期与地址变化、重启、归属校验、重复投递、有界载荷、取消、重定向/公网拒绝、活跃组修改拒绝以及贪心放置会漏选的可用节点组合。控制台完成同机两个 Agent 的真实 HTTP 测量与可视检查；不作为异地带宽证据。

## 真实 GPU 冒烟记录（2026-10-01）

环境：RTX 5060，驱动 616.56，Docker Linux 容器；固定引擎 `e6ab7c1a41054a888ada952eab4c886444c2f5ad`，CUDA 12.8.1，构建架构 `120`。`llama-server --list-devices` 正确列出 CUDA0；`ggml-rpc-server --help` 成功运行。

模型来源：[SmolLM2 135M Q8 GGUF 固定版本](https://huggingface.co/bartowski/SmolLM2-135M-Instruct-GGUF/tree/09816acd5d99df7be770d85ea30822623dab342c)，Apache-2.0。文件 `SmolLM2-135M-Instruct-Q8_0.gguf`，144811360 字节；SHA-256 `5a1395716f7913741cc51d98581b9b1228d80987a9f7d3664106742eb06bba83` 与下载元数据一致。读取 GGUF 核实为 llama 架构、30 层、8192 最大上下文。

在独立、带认证的 Docker 测试网络中，通过平台登记、启用节点、创建 `llama_local` 部署：15 个 GPU 层、1024 上下文、1024 MiB RAM 预留、2048 MiB 主机余量、256 MiB 运行余量与 128 MiB KV 预算。加载和真实短回复预热后变为 ready；经控制面发送简单问候得到 `Hello!`。模型服务及入口都记录到实际载荷字节，模型指标出现实际 prompt/生成 token 计数，没有生成 RPC 服务。

停止后控制面进入 stopped，Agent 确认模型进程退出，节点的 GPU 与 RAM 所有权清空。关闭本机 CPU 特性编译和额外 UI 下载后，最终镜像再次构建成功，真实模型加载和回复复测通过，测试进程已停止。测试只证明真实引擎执行与平台生命周期，不报告 TTFT P95 或持续 token/s；Docker exec 开销、短输出和缓存使本次请求耗时不能用作基准。WSL 的进程显存查询返回 N/A，未将它伪装成进程显存测量。

本机 Docker 构建访问 GitHub 时出现 TLS 中断/拒绝连接，改用宿主机获取同一提交后提供命名构建上下文。可复用脚本（要求干净的源码 checkout，校验 HEAD）：

```powershell
git init tmp/llama-source
git -C tmp/llama-source remote add origin https://github.com/ggml-org/llama.cpp.git
git -C tmp/llama-source fetch --depth 1 origin e6ab7c1a41054a888ada952eab4c886444c2f5ad
git -C tmp/llama-source checkout --detach FETCH_HEAD
./scripts/build-distributed-agent.ps1 -SourceDirectory ./tmp/llama-source -CudaArchitectures 120
```

省略 `-SourceDirectory` 使用原 Dockerfile 在线获取源码；为其他显卡部署时设置对应架构或采用脚本的默认多架构列表。本次只实测 SM120。镜像关闭 `GGML_NATIVE`，采用固定的 AVX2/FMA/F16C 等 x86 CPU 编译特性；不是面向所有旧 CPU 的通用镜像。关闭内嵌 UI 构建和预编译 UI 下载，避免引入额外的浮动前端资源。

当前本地 `18090` 验证入口已更新，升级前状态已备份。本机采集节点继续默认禁用调度。Prometheus/Grafana/Loki/cAdvisor 已启动并检查，Prometheus 目标均为 up，已有 4 条规则校验通过，可查询真实主机内存指标。未启用的可选数据库/消息队列仍显示未运行，不作为业务依赖。
