# 第一版实施计划

> 历史计划：2026-09-23 已增加跨节点 llama.cpp RPC 执行、状态快照和服务监控，当前进度见 [分布式推理与服务监控](分布式推理与服务监控.md)。以下保留最初计划，不能作为当前功能清单。

## 本轮已经落地的代码骨架

控制面领域核心已经具备资源节点、GPU、任务和调度决策模型；调度器执行“先过滤、后评分”，将健康、地域、标签、厂商、显存和拓扑组作为硬约束，将队列、负载、模型缓存、数据就绪和成本作为软评分。内存存储实现了并发安全、状态拷贝隔离、幂等任务记录和原子占卡。

控制面 HTTP 入口已经覆盖资源心跳、资源查询、任务提交、任务查询、任务取消、任务状态回写、按节点领取任务和调度预览。边缘代理从 `nvidia-smi` 读取 GPU，按固定节点身份定时上报，适配 Windows + WSL2 + Docker 的目标运行环境。

控制台与 Compose 基础设施配置已加入：控制台展示资源、可分配 GPU、任务阶段并支持提交/取消任务；Compose 提供 PostgreSQL、NATS JetStream、MinIO、Keycloak、Prometheus、Grafana、Loki 和每台物理机独立的 GPU agent 编排。控制面默认回环绑定，可选 Bearer token；基础设施 profile 目前是适配器占位，不会被误认为已接入控制面业务。

节点管理界面已补齐：可登记、编辑、查看详情、排空、启用和删除算力服务节点；列表显示在线状态、最后心跳、GPU 总量与占用、活动任务和调度开关。新节点默认降级且不可调度，避免仅凭配置记录就把任务投递到尚未连通的服务器。

## 后续工程阶段

1. **运行闭环**：在三台目标 Windows/WSL2 服务器使用 agent 镜像，完成 agent 心跳、任务领取、Docker executor 和 vLLM 试运行；验证单卡、多卡同拓扑组、排队和取消。
2. **持久化与事件**：实现 PostgreSQL adapter、NATS JetStream 事件、Outbox、任务租约和断线重连后的 reconcile；保持领域核心接口不变。
3. **生产安全**：接入 Keycloak/OIDC、租户配额、审计日志、密钥管理、网络分区和 TLS/mTLS；补齐 Prometheus 指标、日志关联和告警。
4. **可靠性**：增加 executor 幂等 token、节点 fencing、心跳迟滞、任务恢复策略、账单用量校正和故障注入测试。
5. **集群化演进**：节点规模和租户并发达到阈值后，再增加 Kubernetes + Kueue adapter；本地调度策略继续由平台控制，避免把业务策略耦合到单一集群实现。

## 需要在目标环境执行的验证

当前开发工作机已用临时 Go 运行时、Docker Desktop 和 Node 完成本地编译验证：`go test ./...`、`go vet ./...`、`npm ci`、`npm run build`、Compose 配置解析和控制面容器 smoke test 均通过。真实三节点 GPU 验收仍需目标环境执行 `deploy/wsl2/bootstrap-agent.ps1`，随后按验收重点验证不兼容不误投、容量排队、幂等不重复执行和断连状态核对。
